# Project adoption snippet

Proposed snippet for a project that has agreed to use Progressive WebUI Workflow. Merge it into the existing project instructions only with applicable authorization. This template does not itself adopt Automation2App or activate another agent.

```markdown
## Web UI workflow

For authorized UI design, implementation, or review, use progressive-webui-workflow when available. Reuse the current task, specification, approved DESIGN.md, stack, and acceptance criteria; run only stages needing work. If the skill is unavailable, report the gap and use an equivalent task-centered review.

Organize controls around user tasks, with essential choices visible, contextual choices grouped where useful, and advanced settings disclosed when needed. For a focused task, aim for one dominant primary action and at most four additional task controls, counting independently actionable options individually. Record utility/navigation controls separately, assess total complexity, and justify exceptions. Do not add a CTA, preset, drawer, or theme merely to match a template.

Preserve material effects, destinations, warnings, confirmations, and result uncertainty. The trusted backend enforces authority. Apply the approved identity; propose brand changes separately. Follow actual component APIs and verify keyboard, focus, contrast, responsive access, and relevant states in the browser. Report unverified criteria and evidence limits; static review alone does not prove runtime behavior or product readiness.

Use the existing plan/tracker and evidence locations. Resolve cross-skill findings through the collaboration reference without recursive orchestration, duplicate specifications, or repeated approvals within unchanged scope.
```
